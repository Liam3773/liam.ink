Security limitation. The password gate only changes what this page shows. It does not secure Firebase by itself. Anyone who can inspect the client can discover the passcode and your configuration. For real production security, use Firebase Authentication plus admin custom claims and locked-down Firestore and Storage rules.
Deployment, rules, and troubleshooting

GitHub Pages: save this file as /admin/index.html, make sure your selected Pages source contains that path, and add an empty .nojekyll file in the root of the publishing source. Visit /admin/ after the deployment finishes. If you use a custom domain, keep the custom domain configured in repository settings, not just with a root CNAME file.

Recommended secure rules — requires Firebase Authentication and an admin custom claim. This is the version you should use for real production enforcement.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isAdmin() {
      return request.auth != null && request.auth.token.admin == true;
    }

    match /reviews/{docId} {
      allow read: if true;
      allow create: if true; // tighten if you later lock public submissions down
      allow update, delete: if isAdmin();
    }
  }
}
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    function isAdmin() {
      return request.auth != null && request.auth.token.admin == true;
    }

    match /reviews/{allPaths=**} {
      allow read: if true;
      allow create: if request.resource != null
        && request.resource.size < 5 * 1024 * 1024
        && request.resource.contentType.matches('image/.*');
      allow delete: if isAdmin();
    }
  }
}

Temporary passcode-only rules — this works with the page exactly as written, but it is not secure because Firebase cannot see your local password prompt.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /reviews/{docId} {
      allow read, create, update, delete: if true;
    }
  }
}
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /reviews/{allPaths=**} {
      allow read: if true;
      allow create: if request.resource != null
        && request.resource.size < 5 * 1024 * 1024
        && request.resource.contentType.matches('image/.*');
      allow delete: if true;
    }
  }
}

Troubleshooting: if image operations fail, verify the exact storageBucket value from Firebase Console; newer default buckets typically use PROJECT_ID.firebasestorage.app while older projects may still use PROJECT_ID.appspot.com. If you intentionally use raw Google Cloud Storage URLs or custom fetch requests instead of the Firebase SDK, configure bucket CORS in Google Cloud as well.

No reviews match the current filters

Try clearing the search box, switching quick filters, or checking that the reviews collection is readable under your current Firestore rules.

This console is intentionally self-contained for static hosting. For a truly secure admin workflow, replace the client-side passcode with Firebase Authentication, set an admin custom claim server-side, and lock both Firestore and Storage rules to authenticated admins only.
