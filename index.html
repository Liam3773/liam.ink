Deployment, rules, and troubleshooting

GitHub Pages note: save this file as /index.html in the top level of the chosen publishing source. If you are publishing a plain static site from a source branch, add an empty /.nojekyll file as well. Keep hero.jpg and photo1.jpg to photo4.jpg beside this file.

Firebase config used here: this file keeps your existing project values exactly, including the Storage bucket: bin-men-fc.firebasestorage.app.

Secure production rules — recommended once you add Firebase Authentication and an admin custom claim.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isAdmin() {
      return request.auth != null && request.auth.token.admin == true;
    }

    match /reviews/{docId} {
      allow read: if true;
      allow create: if true;
      allow update, delete: if isAdmin();
    }
  }
}
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    function isAdmin() {
      return request.auth != null && request.auth.token.admin == true;
    }

    match /reviews/{allPaths=**} {
      allow read: if true;
      allow create: if request.resource != null
        && request.resource.size < 2 * 1024 * 1024
        && request.resource.contentType.matches('image/.*');
      allow delete: if isAdmin();
    }
  }
}

Temporary passcode-only rules — these match the client-side admin gate in this file, but they are not secure because Firebase cannot trust the local password prompt.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /reviews/{docId} {
      allow read, create, delete: if true;
      allow update: if true;
    }
  }
}
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /reviews/{allPaths=**} {
      allow read: if true;
      allow create: if request.resource != null
        && request.resource.size < 2 * 1024 * 1024
        && request.resource.contentType.matches('image/.*');
      allow delete: if true;
    }
  }
}

Troubleshooting:

  • If image upload fails with a Storage URL that looks wrong, check for a bucket typo. A common mistake is accidentally adding an extra character such as firebasestorage.appE.
  • If Firestore says permission denied, publish the correct rules and wait a short time for them to take effect.
  • If GitHub Pages shows a 404, confirm that this file is at the top level of the selected publishing source, and hard refresh after deployment.
  • If you use raw Google Cloud Storage URLs or custom browser requests instead of the Firebase SDK flow, configure bucket CORS accordingly.
