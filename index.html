Deployment, rules and troubleshooting

Deployment note: place this file at /index.html in the repo root (or the top of the selected GitHub Pages publishing source). Keep hero.jpg plus photo1.jpg to photo4.jpg beside it. For a plain static Pages site published from a branch, add an empty /.nojekyll file. Moderation remains separate at /admin/.

Firebase config used here: this file keeps the exact user-provided values, including the Storage bucket bin-men-fc.firebasestorage.app. Public review posting uses Firestore and Storage compat flows only.

Security note: a client-side password prompt is not real security. For production moderation, use Firebase Authentication and Security Rules backed by trusted auth data such as custom claims. Keep delete controls on /admin/, not on this public page.

Secure production rules — use these once /admin/ is backed by Firebase Authentication and an admin custom claim.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isAdmin() {
      return request.auth != null && request.auth.token.admin == true;
    }

    match /reviews/{docId} {
      allow read: if true;
      allow create: if true;
      allow update, delete: if isAdmin();
    }
  }
}
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    function isAdmin() {
      return request.auth != null && request.auth.token.admin == true;
    }

    match /reviews/{allPaths=**} {
      allow read: if true;
      allow create: if request.resource != null
        && request.resource.size < 2 * 1024 * 1024
        && request.resource.contentType.matches('image/.*');
      allow delete: if isAdmin();
    }
  }
}

Troubleshooting checklist

  • CORS or bucket URL errors: if uploads fail with a URL containing an obvious typo such as firebasestorage.appE, fix the exact storageBucket value. Standard Firebase Web SDK upload flows normally work without custom bucket CORS config; custom raw Google Cloud Storage requests may need bucket CORS rules.
  • Permission denied: publish the correct Firestore and Storage rules and wait a short time for them to take effect. Review creation needs Firestore create access and Storage create access. Review reading needs Firestore read access.
  • GitHub Pages 404: confirm that this file is in the selected publishing source, confirm the custom domain if used, and hard refresh after deployment. If /admin/ 404s, that separate file must exist at /admin/index.html.
  • Moderator remember-me: persistent client-side admin sessions are intentionally not implemented here. They belong on the separate /admin/ page only.
